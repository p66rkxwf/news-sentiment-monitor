## 對照（被評模型）

`bert-combined`（現行 production）對同 120 則的判讀，由 GPU 機以
`python tools/judge_qualify.py export-preds` 匯出至 `docs/judge_qualification_model_preds.csv`，
輸入組法與 production 相同：`build_target_text(company_name(ticker), 標題)`。嚴格標準缺此檔時腳本拒絕考試。

## 已知限制（事先揭露）

1. **對照組有利於模型**：07-17、08-05 兩批（60 則）曾用於實驗 #6 的方案選擇，`bert-combined`
   正是在這 60 則上勝出而被選中，其在此的一致率偏樂觀。這使嚴格標準對裁判**更難**過，不會讓裁判佔便宜。
2. **裁判可能知道標題之後發生的事**：考題標題發布於 2026-07～08，`gpt-6-astra` 的訓練資料截止日本文件撰寫時未查證。
   若裁判「記得」後續股價，可能依結果而非標題判讀；此偏誤無法在本設計中排除。
3. **檢定力有限**：120 則下，一致率差距不大時 McNemar 不易顯著；嚴格標準可能讓一個真的較準的裁判也不合格。
4. **批次效應**：同批標題可能互相影響判讀；以打亂順序避免系統性排列，但未完全消除。
5. **標準答案本身有噪音**：財金組標注者間一致率尚未量測；裁判與人工的分歧有一部分可能來自標注本身。
