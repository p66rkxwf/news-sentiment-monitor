# 預先聲明：情緒預警評分器換用（本機 gemma3:27b → 雲端託管模型）

> **本文件必須在執行 `python tools/scorer_agreement.py` 之前定稿並 commit。**
> 門檻寫死在 `tools/scorer_agreement.py` 開頭，與本文件一致；結果出來後不得更改。

- 撰寫日：2026-09-27
- 撰寫時的狀態：**新評分器尚未對任何標題評分**；雲端可用哪個託管模型也尚未實測（候選順序見下）。

## 背景與使用者決策（2026-09-27）

公開部署（news.sekinv.com）改由 GitHub Actions 每日排程，免費執行環境沒有 GPU，
跑不動本機的 gemma3:27b。使用者決定：

1. **評分改用 Google AI Studio（Gemini API）的免費託管模型**，沿用同一份目標導向提示詞
   （`llm_review._SYSTEM_PROMPT` / `_user_prompt`）。
2. **換評分器＝換版本字串**（`llm-gemini:<模型>`），與本機分數（`llm-gemma3:27b`）分開存、不混算。
   看板的 20 日基準只用新評分器的分數，所以要先回補一段歷史分數。

候選模型依序實測，第一個「存在、能正常回答」的即採用：
`gemma-3-27b-it` → `gemma-4-31b-it` → `gemma-4-26b-a4b-it` → 免費層的 Gemini Flash-Lite。
即使是同名的 Gemma 3 27B，託管版與本機 Ollama 版的量化、chat template 不同，仍視為不同評分器。

## 要回答的問題（單一）

**新評分器對同一批台股中文標題的判讀，是否與本機 gemma3:27b 足夠一致，使得既有的回測結論
（`docs/alert_backtest.md`：事前示警率與隨機響鈴無法區分，p = 0.983）可以延用到新評分器？**

這不是在問「哪個比較準」——兩者都沒有台股中文標題的人工標注可對照。一致只代表「換了之後
行為沒變」，不代表「對」。

## 比較資料

- 兩個評分器都評過的 (ticker, 標題)。本機評分涵蓋 2024-07 ~ 2025-11（回測期間）與 2026-08 ~ 2026-09-26（線上）；
  新評分器的回補從 2026-07-15 起，重疊段主要是 2026-08 ~ 2026-09。
- 盤勢報導標題一律排除（與看板規則相同）。
- 不另挑子集、不因結果排除任何標題。

## 指標與判定門檻

| 指標 | 用途 |
|---|---|
| **Cohen's κ**（逐則標籤，3 類） | **主要判定指標** |
| 原始一致率＋Wilson 95% CI | 報告用 |
| 3×3 混淆矩陣 | 報告用 |
| 舊判負面 → 新也判負面的比例 | 報告用（預警只看負向偏離，這一格的落差最關鍵） |
| 每日分數 Spearman（ticker×交易日） | 報告用（看板實際使用的量） |
| 覆蓋率 | 前提條件 |

判定（依序套用）：

1. 成對標題 < 200 → **不下結論**。
2. 覆蓋率 < 95% → **不下結論**，先補齊回補或查解析失敗。
3. κ ≥ 0.60 → **採用**。
4. 0.40 ≤ κ < 0.60 → **採用，但須揭露**：本機評分器的回測結論不適用於新評分器（前端預警頁與設定頁、README 都要寫）。
5. κ < 0.40 → **暫停採用**：優先懷疑提示詞送法或解析有誤（例如 systemInstruction 被忽略、答案格式不同），
   修正後重跑；確認不是 bug 才改試下一個候選模型。

門檻的依據：κ 0.40–0.60 一般稱為中度一致、≥ 0.60 為高度一致。本專案量過 gemma3:27b 對財金組
人工標注的一致性為 κ 0.339（`docs/judge_qualification_prereg.md`）；兩個 LLM 之間的一致性若還不到
中度，差異就和「換一個標注者」差不多大，舊回測結論不能直接沿用。

## 不做的事

- **不在新評分器上重跑 2024-09 ~ 2025-12 的回測來取代舊結果。** 新候選模型的知識截止多半晚於 2024-08，
  回測期間的事件可能已在訓練資料裡（舊回測選 2024-09 起算正是為了避開 gemma3 的知識截止）。
  若要重跑，須另寫預先聲明，並把污染風險列為主要限制。
- 不依一致性結果回頭調整提示詞以「提高一致率」：提示詞只能因 bug 修改，且須在報告中說明。
