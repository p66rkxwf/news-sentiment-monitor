# 預先聲明：情緒異常預警的歷史回測

> **本文件必須在執行 `python tools/alert_backtest.py run` 之前定稿並 commit。**
> 回測最常見的自欺方式是「看過結果再調門檻」或「只挑系統抓到的事件來展示」。
> 下列規則在任何事件期間的情緒分數產生之前寫死；結果出來後不得更改。

- 撰寫日：2026-09-14
- 撰寫時的狀態：**回測期間（2024-09 ~ 2025-12）尚未產生任何情緒分數**。事件選取只用價格資料。
- 回測期間之外做過的開發檢查（不影響本回測）：
  1. 管線試跑：台積電 2026-09-10～11，43 則，實際送 LLM 評分
  2. 標題過濾檢查：10 檔股票 2026-09-11 的 63 則標題，只套過濾規則、未評分
- 誠實揭露：撰寫前曾人工檢視部分候選事件當天的 FinMind 標題，目的是確認新聞源的時區與成因，
  未對這些標題計算任何分數；下列門檻沒有因此調整。

## 使用者決策（2026-09-14）

1. **評分器採 gemma3:27b 直接判讀中文標題。** 不採「翻譯後交給 bert-combined」：兩層模型的誤差會疊加。
   代價是 gemma3 未經台股中文標題的人工標注驗證，須在報告與 demo 中主動揭露。
2. **盤勢報導標題不計入。** 試跑中判為負面的標題大多只是在描述已經發生的下跌，
   不排除的話，「事前示警」可能只是「昨天已經跌了」的回聲，無法支持「情緒領先價格」。

## 假說（單一，事先指定）

**H1：對價格規則選出的個股異常下跌事件，系統在事件日前 5 個交易日內至少發出一次警示
（watch 或 high）的比例，高於同批股票背景警示率所隱含的隨機響鈴機率。**

- H0：事前示警率與隨機響鈴無差異。
- 事件日**當天**的開盤前示警**不計入 H1**：跳空開低時投資人來不及反應，那是「即時」不是「提前」。

## 主要指標與檢定

- **事前命中率**＝事件日前 5 個交易日內至少一次 watch/high 的事件數 ÷ 事前窗有可評估資料的事件數
- **隨機基準**＝1 − (1 − p)⁵；p＝背景期（事件日前第 10～6 個交易日）非「資料不足」股票日中的警示比例
- **檢定**：單尾二項檢定，α = 0.05
- **次要指標（僅描述，不作為裁決依據）**：事件日開盤前示警率、首次示警的領先交易日數、觸發證據標題

## 事件選取規則（寫死）

| 項目 | 規則 |
|---|---|
| 期間 | 2024-09-01 ~ 2025-12-31（評分器 gemma3:27b 知識截止約 2024-08；更早的事件，它可能讀過事後報導） |
| 股票池 | 預警股票池 49 檔（鏡像 stock-trend-assistant `STOCK_POOL`） |
| 價格 | yfinance 還原收盤價；異常報酬＝個股日報酬 − 加權指數日報酬 |
| 觸發 | 異常報酬 ≤ −7% **且** 個股日報酬 ≤ −5% |
| 排除 | 除權息日（FinMind TaiwanStockDividendResult）——實測 yfinance 未還原台灣大 2024-07-08 的除息 |
| 去重 | 同一檔 20 個交易日內只取第一次 |

2026-09-14 以此規則選出 21 件（清單以 `python tools/alert_backtest.py events` 的輸出為準）。

**敘事型事件（手挑，只展示、不計入 H1）**：廣達 2025-02-03（DeepSeek＋北美關稅，春節休市期間發酵）、
鴻海 2025-04-07（對等關稅，清明連假期間宣布）、國泰金 2025-05-05（新台幣急升）。

## 系統設定（寫死）

| 項目 | 設定 | 來源 |
|---|---|---|
| 每則分數 | P(正) − P(負) | 使用者需求 |
| 交易日分數 | 該交易日開盤前（台北 09:00）可得標題的平均 | 資訊時點規則 |
| 判斷 | z = (當日 − 前 20 個交易日平均) ÷ max(σ, 0.10)；z < −1.5 watch、z < −2 high | 使用者需求（σ 下限為實作時設定） |
| 資料不足 | 當日 < 2 則，或基準 20 天中 < 10 天有新聞 | 實作時設定，未經回測調整 |
| 新聞源 | FinMind TaiwanStockNews，濾除 CMoney 論壇貼文、同標題取最早發布 | |
| 盤勢報導標題 | 符合下列任一 regex 即不評分、不計入（先做 NFKC 正規化） | 使用者決策 2；最後一條由開發集補上 |
| 評分器 | `llm-gemma3:27b`，實驗 #6 B2 組的同一份目標導向提示詞 | 使用者決策 1 |

盤勢報導規則（`config.ALERT_PRICE_REPORT_PATTERNS`，本表為準）：

```text
跌\d+元   漲\d+元   收跌   收漲   跌停   漲停   開盤   盤中
成交量   三大法人   融資   融券   [跌漲挫](逾|近)?[\d,.]+點
```

## 盤勢報導過濾：開發集檢查（回測期間之外）

| 樣本 | 結果 |
|---|---|
| 台積電 2026-09-10～11（43 則，已評分） | 過濾 15 則；判為負面的 13 則中過濾 12 則，剩下 1 則是籌碼報導（「爆調節賣壓」） |
| 10 檔股票 2026-09-11（63 則，未評分） | 過濾 14 則 |

**已知代價（事先承認）**：台灣財經媒體常把原因和股價寫在同一則標題裡，這類標題會整則被濾掉。
世芯-KY 2026-09-11 因「高通攜手 AWS」跌停，當天 8 則帶原因的標題中有 7 則因含「跌停」被濾掉，
唯一留下的是「高通攜AWS對世芯-KY影響有限」。

這些標題都在當天開盤後發布，依資訊時點規則歸到下一個交易日，**不影響該事件的 H1 判定**。
代價會落在三個地方：
- demo 的證據標題
- 事件後的交易日
- 「先出利空、小跌，隔日才大跌」的多日型事件

**已知漏網**：「早盤挫逾2%」「族群重挫，某股領跌」這類寫法不在規則內，仍會計入。

## 裁決規則（事先寫死）

| 結果 | 裁決（demo 可以怎麼說） |
|---|---|
| 事前窗可評估事件 < 5 | 資料不足，不做推論 |
| p < 0.05 | 可說「在 n 件價格事件上，事前示警率高於隨機」，**必須同時報背景警示率與 n** |
| p ≥ 0.05 | **不得使用「提前預警」「事前偵測」等說法**；只能呈現「開盤前即時示警＋證據標題」 |

**不允許的事**：
- 看完結果後調整 σ 門檻、σ 下限、最少則數、基準長度、盤勢報導規則或事件規則
- 移除「沒有新聞」或「沒示警」的事件，或在 demo 中只展示命中者
- 用敘事型事件的結果補強主結論
- 換其他 LLM 重跑後挑較好的一次（換評分器視為新實驗，另寫預先聲明）

## 已知限制（事先承認）

- 事件數約二十件，檢定力低；「未達顯著」不等於「證明無效」
- 背景期緊鄰事件，事前醞釀會同時抬高背景警示率，使檢定偏保守
- 評分器未經台股中文標題的人工標注驗證
- 盤勢報導過濾有上述代價與漏網；過濾後當日標題變少，中小型股更容易落入「資料不足」
- 新聞為事後回補：資料源宣稱的發布時間不等於當時系統抓得到；事後刪除的新聞不會出現
- 有些價格事件本來就沒有新聞原因（撰寫前檢視已看到數例），情緒預警不可能提前示警這類事件
